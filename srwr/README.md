## 2. V1 补丁本体

**功能**：动画开关 ON 时，战斗动画播放中按住 B → 动画立刻收尾进入结算（走游戏官方结束路径，伤害数字/经验值/击坠全部正常）。动画开关 OFF 时不受影响（本来就没动画）。

### 钩子
`0x080028AA`（每帧读键函数 0x8002864 内），原4字节 `61 46 08 80`（`mov r1,ip; strh r0,[r1]`，ip=0x03002AA8）→ `bl 0x08093670`。

### 代码洞 `0x08093670`（0x58字节，原版全零已断言）
```
push {lr}
ldr r1,=0x03002AA8      ; 键值镜像(官方)
strh r0,[r1]            ; 复刻原指令
movs r1,#2
ands r0,r1              ; B键按下?
beq done
ldr r2,=0x02014AF0      ; 场景请求字节 REQ
ldrb r0,[r2]
cmp r0,#2               ; 动画场景中?
bne done
ldr r1,=0x03001320      ; 当前模式号
ldr r1,[r1]
cmp r1,#2               ; 模式2=战斗动画显示?
bne done
ldr r2,=0x03001080      ; 模式状态数组基址
adds r1,r2,r1           ; = 0x03001082 (模式2的状态字节)
ldrb r0,[r1]
cmp r0,#9               ; 状态9=动画播放中(官方完成回调同款检查)
bne done
; ---- 四重闸门通过, 复刻官方完成回调 0x803AD88 的转换 ----
ldr r2,=0x03001080
adds r2,#1              ; 0x03001081 = 模式1的状态字节
movs r1,#3
strb r1,[r2]            ; phase[1]=3   (结算相位)
ldr r2,=0x03001320
movs r1,#1
str r1,[r2]             ; 模式=1       (切到战斗编排模式)
ldr r2,=0x08013B21      ; 战斗编排帧函数(Thumb位)
ldr r1,=0x03001108      ; task0.func
str r2,[r1]             ; Task0函数指针替换 = 官方模式切换机制!
done:
pop {r1}
bx r1
```

**原理一句话**：游戏"换模式"=换 Task0 的函数指针（0x8002790 就是干这个的API）。动画自然结束时官方回调做的事 = 写模式1状态3 + 切模式 + Task0换战斗编排器；下一帧任务分发器调它 → 序列器看到状态3 → 走官方 case3（animend(1)：杀动画任务+重建场景+REQ=1+dispatch(1)）→ 结算画面。补丁只是在动画播放中途人为执行同款转换，时序与官方完全一致。

## 3. 核心架构（实测破译）

### 3.1 模式系统（本引擎的中枢）
- **`[0x03001320]` = 当前模式号**（word）
- **`0x03001080 + 模式号` = 该模式的状态字节**（每模式1字节状态机）
- getter `0x8002ACC()`：返回 `[[0x03001320] + 0x03001080]`
- setter `0x8002AAC(模式, 状态)`：先写 `[0x03001320]=模式`，再写 `[0x03001080+模式]=状态`
- 已见模式：**1=战斗编排**（状态3=结算相位），**2=战斗动画显示**（状态9=播放中），3/0xD/0xE/0x10/0x11/0x12/0x1E/0x20/0x31=其他（地图/菜单等，由0x8004xxx模式管理器成对设置）

### 3.2 任务系统
- 任务表 `0x03001100`，16字节/条：`{+0:type, +2:state, +8:func_ptr}`，约32条
- 分发器 `0x8002804`：每帧遍历，**state==1 才调用 func**（state 0xFFFF=休眠）
- **Task0 = 模式帧任务**（永活），`0x8002790(func)` = `task[0].func = func`
- **模式切换 = Task0.func 指针替换**：战斗编排帧=`0x08013B20`，动画显示帧=`0x0803D878`（注册链在 0x8004E54-0x8004EA2，每项 `ldr r0,=func; bl 0x8002790; b tail`）
- Task0 帧函数（动画显示模式 0x0803D878）每帧轮询 `[0x03001C98]`：0=演出中（含START检查），1=演出完毕→调 0x803D814 显示系统总复位

### 3.3 战斗序列器（模式1的逻辑）
- 帧函数 `0x8013B20` → 序列器 `0x8013280`（`push {r4,r5,lr}` 起）
- 链尾 `bl 0x8002ACC; subs r0,#1; cmp r0,#7; bls 跳表@0x8013414`（getter值1-8）
- **case3 @0x801359C：`movs r0,#1; bl 0x80281A0`** = 官方"动画→结算"切换
- `0x80281A0(1)`：杀任务(0x8002FA8/0x80030B8) + 重建ctx([0x02014AC0]) + **REQ=1 + [0x02014AF1]=r3** + `dispatch(1)` + r6==2时额外清缓冲
- **序列器只在模式1运行**（动画期间模式2，序列器根本不跑——这是V5失败的根源）

### 3.4 场景请求
- **`[0x02014AF0]` = 场景请求字节**：2=动画场景，1=结算场景；ctx指针在 `[0x02014AC0]`（REQ=ctx+0x30）
- 场景调度器 `0x80269B8(r0)`：写REQ + 按场景生成驱动任务（场景1→类型0xD，场景2→类型0xE）
- **REQ只是记录，不是开关**——动画任务不轮询它（写1无效，实测）

### 3.5 战斗脚本状态机
- `0x80125C8(N)`：`G=[0x02014504]` ← N，并跑进入动作（状态2-29的进入动作=0x8026AD4清[0x02014AF1]）
- 事件跳转 `0x8034BFC(idx)`：调事件函数 `table1[idx]`（表@0x080950A0，8B/项，经0x8059E30的bx桩调用）+ 注册续延 `0x8000EF4(0,h1,h2)`（存入 0x03001640+idx*16 的 +A/+C）+ 设脚本状态2
- table2 @0x80951E8：续延参数（-4=推进队列等特殊码）
- 攻击动画事件=**7号**（func 0x802E030：调0x8014E14搭动画场景+开信息窗）；结算事件=0x24号
- 脚本状态机**事件驱动、无每帧轮询**（wp观察点实测：18秒动画期间G纹丝不动）

### 3.6 动画完成回调（官方跳过的真身）
- 动画显示系统播完 → 终结器（含0x57次单位循环清理，0x803B9EC 处）→ 调 **`0x803AD88`**：
  1. `getter()==9 → setter(1,3)`（切模式1+状态3）
  2. 顺带计数（getter()==1 且 [0x03003338]==1 时 [0x03003350]++）
  3. **`[0x03001C98]=1`**（Task0的"演出完毕"门）
- 之后 Task0/模式系统接管，序列器跑 case3 → animend(1) → 结算

### 3.7 输入系统
- 读键函数 `0x8002864`（每帧），钩子窗口 0x080028AA-0x080028AD
- 键镜像：**`[0x03002AA8]`**=held副本（钩子处经ip写入，补丁复刻点）、`[0x03001634]`=另一副本（原生START检查用）
- GBA键位：A=bit0, **B=bit1**, Select=bit2, Start=bit3

## 4. 原生机制与失败路径（重要教训）

| 尝试 | 结果 | 原因 |
|---|---|---|
| 写 `[0x02014AF0]=1`（V1期） | 无反应 | REQ是调度器入参不是开关，动画任务不轮询 |
| 从读键钩子调 `0x80269B8(1)` | 无反应 | 只生成结算任务，没杀动画任务 |
| 从读键钩子调 `0x80281A0(1)` | 卡死循环 | 完整清理函数不能从读键上下文调（重入/时机） |
| **写 `phase[2]=3`（V5）** | **动画无限循环！** | 只改了状态没切模式；完成回调检查`==9`失败→永不切换→死循环 |
| 置 `[0x02000C2C]=1`（V6，原生START标志） | 无反应 | 标志只在场景检查点被消费（开场/结算后），动画中无人轮询 |
| 写 `phase[1]=3 + 模式=1`（V7） | 无反应 | 模式变量本身不驱动任何东西 |
| **V8 = V7 + `task0.func=0x08013B21`** | ✅成功 | 补上了官方模式切换的核心：Task0函数指针替换 |

### 原生"START快进"机制（已破译但不可用于中途跳过）
- Task0（显示模式）每帧：`相位==9 && (keys&0x3FF)==8`（单独START）→ `[0x02000C2C]=1`
- 消费者 0x8026C18 / 0x801A076：标志≠0 → `0x8034BFC(0x24)`（跳结算事件）——但消费点在场景切换检查点，动画播放中不执行
- 战斗开始的 case 会清零该标志（0x80134AC/0x80135EE）

## 5. 调试环境速查

- `emu/harness.py serve srwr_bskip.gba run_r` — 测试台（自编译mGBA GDB版），命令队列 `q/cmd.txt` → 日志 `log/out.txt`，断点事件 `log/events.txt`
- `bpa <addr> <标签>` 自动断点（记r0-r3/lr）；**低频断点安全，每帧断点=冻屏**
- **wp 观察点可用**（`wp <addr> <len>`，写命中记pc）——抓"谁写了这个变量"神器
- `key <键名>` PostMessage注入；`shot <png>` 截图；`pokeif` 条件写内存
- 断点命中后 lr 分析注意：case入口的lr是残留值（跳表用mov pc），只有函数头bp的lr才是真实调用者

### 关键断点标签速查
| 地址 | 含义 |
|---|---|
| 0x0801359C (PH3) | 序列器case3=官方动画→结算（自然结束时触发） |
| 0x080135B0 (PH5) | 序列器case5=战斗开始（animend(2)） |
| 0x08034BFC (SCRIPTJUMP) | 脚本事件跳转（r0=事件号，lr=调用者） |
| 0x080281A0 (ANIMEND) | 官方结束清理（r0=1结算/2开场重置） |
| 0x08014E14 (ANIMON) | 动画场景搭建（高频，勿轻易bp） |

## 6. 构建/补丁工具链

- `build_rom_r.py`：双ROM构建，capstone全量自验（指令序列+**操作数方向断言**+分支目标+每条ldr池值核对+站点bl+回读），`--dry`空跑
- 手写Thumb教训：strb操作数方向写反过一次（0x7011↔0x700A），全靠操作数级断言抓住；b_enc/ldrpc_enc第一参数必须是实际发射地址
- BL扫描器坑：Thumb BL偏移是**23位符号扩展（bit22=0x400000）**，写错符号位会漏掉所有负偏移调用点（本项目踩过：0x8002AAC/0x8000F04/0x8014E14的调用者全在更高地址）
- `patch_r.html`：XDF1格式（`"XDF1"+源CRC+目标CRC+输出大小+压缩大小+deflate-raw(XOR差异)`的base64），DecompressionStream解压，CRC32双向校验；已浏览器端到端实测（识别/打补丁/已打版提示/震动版全通过）
- 补丁生成：`zlib.compress(xd,9)[2:-4]` 剥掉zlib头尾即 deflate-raw
