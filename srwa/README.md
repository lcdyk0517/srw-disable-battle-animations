# 超级机器人大战A (GBA) 逆向解析笔记 — V1 定版

**V1 功能 (2026-10-09, 用户实测全部通过)**:
1. 系统菜单第6项 `动画 ＯＮ/ＯＦＦ` 开关, 按A即时切换(菜单保持打开, 文字立即变)
2. ＯＦＦ(FLAG=0xA5): 普攻/反击动画全跳过, 走原生结算(不损失伤害)
3. ＯＮ(FLAG=0): 完全原版
4. 动画播放中按住B → 立即跳过当前动画(原生R+A场景跳过机制)

交付物: `emu/build_rom.py`(唯一构建源, capstone全量自验) → `emu/run/srwa.gba` (汉化版)
　　　　`emu/build_rom_jp.py` → `emu/run_jp/srwa_jp.gba` (日文原版, 同一套补丁)

## 1. ROM基本参数

## 2. 文本编码

- ROM内**无Shift-JIS字符串**(汉化组重编码), 保留**英文物件名/调试格式串**——逆向突破口:
  - 场景名表 `START SCENARIO - %2d` / `PLAYER SELECT` 等 @0x60600–0x60A14
  - 战斗资源名表 `ENDFLAG/KAGE/EBH/EHH/EHF/ESF/UNIT...` @0x60A14, 2134条×16字节
- 双字节码表(汉化重映射)。**字库拉丁区连续排布: 字母 = 0x8260 + 字母序号**(实证: 826F=Ｐ 826E=Ｏ 连写显示"PO")
  - Ｏ=826E Ｎ=826D Ｆ=8265 → "ＯＮ"=826E826D, "ＯＦＦ"=826E82658265
- 菜单项字符串库 @0x0806E760一带(回合结束@0x0806E7AC 等), 0000结尾

## 4. 文件系统与ECD压缩

### 4.1 双文件组结构

解析函数 `0x8002650(group, idx)` → 文件ROM指针:

| 组 | 文件数 | 数据基址 | 偏移表 |
|---|---|---|---|
| 0 | 6956 | 0x0810FA20 | 0x080076C28 (u32相对偏移) |
| 1 | 1324 | 0x0869AC00 | 0x08007D8DC (裸u16流, 无ECD头) |

### 4.2 bank名表(前2134个bank有名)

- 名字字符串 0x60A14起16字节/条; 名字指针表 0x7F4A4 (2134×u32, 顺序=bank号)
- 分段: bank 0–388 `UNIT`(机体立绘) | 389–948 `WS`(武器特效) | 949–1583 `ESF`(战斗动画分件) | 1584–2062 `EHF`(特效帧) | 2064–2115 `EHH`(战斗背景) | 2116–2131 `EBH`(背景变体) | 2131–2133 `KAGE/ENDFLAG`

### 4.3 ECD压缩格式 (完全破解, 编解码器齐备, 回验全部通过)

```
偏移  大小  内容
+0x00  4    'ECD\x01' 魔数
+0x04  4    u32BE SCR头原样字节数 (恒为8)
+0x08  4    u32BE 数据流总长 (含SCR头)
+0x0C  4    u32BE 解压后总长度
+0x10  ...  "SCR\0"+w+h+... 或直接数据 (ECD头+3字节≠0=有压缩流)
```
LZSS细节 (解压核心 0x8003F84):
- flag字节LSB优先: 位1=字面量(1字节), 位0=匹配(2字节: b1=偏移低8位, b2高2位=偏移高2位→**10bit绝对窗口位**, b2低6位=长度-3 → 3–66字节)
- 滑动窗口1KB @0x03000C30 预零, **写指针初值0x3BE**; 复制时窗口同步更新(可自引用重叠复制=天然RLE)
- 位流哨兵: 0xFF00掩码下探, 读完8项取新flag字节; 字节读尽返回-1结束

块类型探测 `0x80064D4`(tag): IMG=1 / PLT=2 / SCR=3 / PAT=4 / TIM=5。组0实测分布: PLT 1445 / IMG 1431 / SCR 475 / ATR 61。

### 4.4 通用加载器

`0x8002928(类, 组, idx, 模式...)` — 查表→(ECD且+3≠0)解压→按模式送VRAM/RAM。包装 `0x8002684`(ECD头+3字节=压缩标志)。

## 5. 战斗动画资源体系

### 5.1 动画定义表 (核心)

**`0x080A0168`, 128条 × 12字节**, 动画ID直接索引:
```
+0/+2 u16 bankA1/A2 (WS图)   +4 u16 bankC (0xFFFF=无)
+6/+8 u16 主/副ESF分件bank    +10 u16 类别(0–10; 类别5×17条=地图炮特效族)
```
- 装载 `0x8010878(动画ID, 模式)`: 模式0=精灵演出 / 模式2=全屏BG(MAP武器, SCR→BG VRAM 0x06001800)

### 5.2 战斗脚本文本

- 映射表 `0x080AF578`: 动画ID→组1bank (entry[i]=i+1)
- 脚本=u16操作码流, 解释器: 阶段0x10–0x13 (`0x3AEB4`等), 经表`0x080B16C2`/`0x080B13B4`映射后调 `0x8038DB0(动画ID,侧)` — 写 `[0x0200D910+0x5E]`(=0x0200D96E) 并装载

### 5.3 武器→动画ID选择

- 武器记录 72字节(0x48)/条, EWRAM工作副本 `0x020058C0`
- 战斗上下文 `+0x3E`=武器类别(0–11), 12路跳转表 `0x38B68` → 类别处理函数 `0x38140–0x38B14`
- 类别11入口读武器记录动画字段 `+0x1A/+0x1E/+0x20/+0x22`

### 5.4 单位表与SCR

- 单位表 `0x080AEEBC` 16字节/单位: `+0xC`=攻侧动画ID, `+0xD`=守侧; SE音效字段@0x10E90一带
- SCR(全屏BG): 175个ESF组中69组含SCR块(地图炮/必杀需要, 普攻多为纯精灵)

## 6. 战斗切镜架构

### 6.1 命令系统 (地图侧⇄切镜侧IPC)

- 发送 `0x8002378(命令号,参数)`: 命令号→`[0x03001150]`, 参数→`[0x03001090+命令号]`
- 读取 `0x800238C()`; 分发器 `0x8003814` (帧任务, 跳转表`0x8003850` 42项)
- 关键命令: 0x01=切镜总导演(参数1=普攻) / 0x04=战斗步骤机场景(帧任务0x49F34) / 0x28=结束回地图

### 6.2 战斗序列控制器

- `0x803F1DC` 序列主循环: 挂起帧计数`[ctx+8]`, 阶段字节`[ctx+0xC]`, 17阶段跳转表`0x3F288`
- 阶段0x10–0x13=脚本字节码解释器; 初始化`0x803E394`(动画ID→资源指针→设初始阶段); 阶段设置`0x8039808`
- 切镜状态机: 状态字节`0x0200E644`, 处理函数表`0x080BEEBC` 14项, 主帧任务`0x49F34`
- **原生跳过闸: `[0x0200E6A0]`≠0 时 R+A按住→state直跳0x0D**(`0x49F74-9A`)

### 6.3 键盘系统 (B跳过的挂钩点)

- 键读取器 `0x8002250` **每帧全状态运行**; 键值=按位反转的按下位流(B=bit1)
- 镜像 `[0x03001148]`(按住) / `[0x03001194]`(副本) / 新按`[0x03001144]`
- 站点 `0x0800225C` (ldr r1,=镜像 + strh r0) 4字节→bl cave6s, 唯一可靠的每帧钩子

## 7. 普攻/反击流程与跳过原理 (全部实测)

### 7.1 普攻流程

1. A确认→结算(`0x31xxx`), 动画ID写`[0x0200D96E]`
2. 步骤计划经中央规划器`0x802BEA8`写`[0x02006BE0]`(步骤0x00–0x2D, 表`0x08030668`)
3. 分发器`0x8030644`逐步执行; 分岔在`0x8031546`(`0x801A398`==0→step 0x18切镜, 非0→0x19跳过支)
4. **step 0x18处理(0x802DAE0)内部"中途停靠站"才是动画真入口**:
```
0802DAE0  step 0x18入口: 等A(0x2DB0C) → 黑场对(0x2DBAE)
0802DBB6  bl 0x800CD8C(0x11)  ← 停靠站: 设场景状态0x11→0x12→cmd(4,2)→全屏切镜
0802DBC6  检查[0x9F38C] → 单位归位段
0802DC5A  写标志[ctx+0x4E]=0x18 → 屏幕恢复 → bl 0x8030858   ← 原生完成段!
0802DC7E  设场景状态0x19 → bl 0x8015AFC → 发0x58信号 → 出函数
```
5. 原生计划全序列: `0x00×3→0x01→0x10→0x18→0x15→0x2C→0x1B→0x13`
6. **跳过原理(FLAG=0xA5)**: cave3把停靠站跳到0x0802DC5B原生完成段——全部簿记(标志/0x19/0x58)原生保留, 伤害不损失

### 7.2 反击/敌攻流程

```
步19编排器(0x802DDA0)选择阶段逐帧轮询(等玩家输入, 不可跳)
按A确认 → 0x0802DE70: movs r0,#0x11; bl 状态设置器  ← 唯一启动点(每场反击恰好1次)
→ 场景0x11→0x12 全屏动画17秒(纯演出, 步19不运行, 伤害已在0x2DE08块算完)
→ 0x00(场景关闭) → 0x0E→0x13→结算→回MAP
```
- **伤害计算在启动点之前完成**——动画纯呈现, 可无损跳过
- 原生无动画结算段(0x2E0BA): `0x800e2b8(0,-1)`→相位0x18→`0x800d9d0`→`0x802574c`→`0x8030858(0)`→发状态0x19→`0x8015afc`, 与普攻完成段同构
- **跳过原理**: cave5在启动点复刻该结算续行链(不重复已做的伤害/stores/黑场)

### 7.3 B键动画跳过

- 机制: B按住且场景`[0x02005408]`==0x12 → 写`[0x0200E6A0]=1`(解锁原生跳过) + 键值|=0x101(R+A位) → 游戏自己的场景机完成跳过+清理
- 伤害弹字=0x801A2BC(0x0F状态处理器调用); R+A跳过绕过0x0F↔0x1A循环→**跳过的那场无MAP伤害弹字**(原生特性)

## 8. 系统菜单架构 (全部实测)

### 8.1 菜单状态与项数

- 状态区 `[0x02006BF0]`: +4=攻击目标索引, +6=光标, +8=窗口宽, +0xC=窗口高, **+0x12=项数**, +0x14=页参数
- 项数写入点 `0x08026BFC`(movs r0,#5→strh [r3+0x12]) — 改6后光标可达第6项
- A键分发 `0x802C854`: 光标≤4→`0x802C87A`查表分发(5个处理函数=规划器步) / >4→`0x802C8CA`只发0x58关菜单

### 8.2 窗口渲染体系 (描述符→条目→画布)

```
[0x03003AA8] → 描述符表@0x080A0E50 → 项#27(系统菜单) → 描述符@0x080A0D90
{flags=0x049B(选画布样式), count, itemPtr} → 条目数组 8字节/条 {x, y, 调色板, pad, 字符串指针}
渲染: 0x800C89C(x,y,窗口号,0) → 0x800C6CC(画框) → 条目循环 bl 0x8008928(串,x,y,调色板)
```
- 原数组@0x080A0AEC仅7条: 标题(y0,x18) + y2x18后缀(回合/资金区的字) + 5个菜单项(y2-y10); **第6行(y12)无条目→永远空白**(项数补丁只放开光标)
- 条目y单位=半行: 显示行 = y+1 (canvas row); 菜单行距2行(16px)

### 8.3 窗口背景画布 (ECD压缩资源)

- flags 0x049B → 样式记录@0x0823E5D0 → 解压出全宽画布 w30×h13:
  - **左框 rows2-12** = 菜单本体(顶边d320/d322/d720, 体d321/d336/d721, 底db20/db22/df20)
  - **右框 rows0-4** = 回合/资金信息框
- 第6项文本画在canvas row13 = 画布外→**加高画布到15行**(体行模板必须取row5: 左框体+右侧空白; row3右侧带信息框体会误延伸右侧)
- 画布瓦片存储形: 空白=0x0000, 框体=索引值; 绘制时0→0x03FF(空白瓦片), 非0→+=0xD300(调色板D)

### 8.4 第6项动态文字

- 条目8 `{x=0,y=0x0C,pal=0x0F,串指针=0x0203FF10(RAM)}` → cave6s每帧按FLAG写入ＯＮ/ＯＦＦ字节(开机即正确初始化)
- cave4切换FLAG后**立即同步字符串**(每帧同步发生在菜单处理之前, 不补写则重绘见旧串慢一拍) + 调`0x800C89C(0,1,0x1B,0)`重绘 → 按A即时显示新状态

## 12. 日文原版移植 (V1-JP)

### 12.1 两版ROM对比 (实测)

| 项 | 汉化版 | 日文原版 |
|---|---|---|
| 文件 | `超级机器人大战A[WGF](v1.1)(修正)(简)(JP)(65Mb).gba` | `Super Robot Taisen A (Japan).gba` |
| 大小 | 0x82028C (8MB+131,980B附加) | 0x800000 (标准8MB) |
| 代码区0x1000-0x60A14 | **逐字节100%一致 (0差异)** | 同左 |

汉化版**只改了数据**, 差异分布:
- 0x060000-0x07FFFF (~50KB): 文本/字符串区(菜单串内容不同, 但**条目数组里的字符串指针仍指向同地址**→日版自动显示原文)
- 0x120000-0x130000 (~63KB): 字库/图形
- 0x6D0000-0x7FFFFF (~1.1MB): 大图形包
- 文件尾附加0x2028C字节(与补丁无关)

**关键数据点全部同址同值**(实测逐项核对): 文件表0x08076C24 / 样式表项[0x49B]@0x08077E90 / 菜单条目数组0x080A0AEC / 菜单描述符0x080A0D90 / 窗口表0x080A0E50 / 画布记录0x0823E5D0。
三个洞区(0x76A78/0x994F4/0x99728)在日版同样全零。

## F. 编码/工艺教训

1. **分支/字面量发射偏移必须以最终布局逐条核算**——同一种"目标写成旧注释偏移"错法连犯3次(bl占4字节/池对齐都会移位)
2. **手写Thumb操作码三类高频错**: 字节序抄错(0221≠2102, movs r1,#2=0x2102) / 寄存器字段错(BC01=pop{r0}≠pop{r1}) / 立即数偏移算错(str [r2,#4]=0x6051≠0x6151)——capstone只查助记符不查寄存器/操作数, **必须人工反汇编全洞核对语义**
3. 洞内尾返回必须push{r4,lr}+pop经寄存器bx; bx lr在bl覆盖后=自旋死循环
4. RAM标记必须考虑开机垃圾初始化(演示流程会触发!)
5. 毒存档(挂起槽)污染测试结论——崩溃复现先换全新sav隔离变量
6. "全零区"≠死区: 需完整业务流程跑过才算安全
7. 交互等待(选择画面)与演出等待共用机制——跳过等待类补丁必先确认无交互场景依赖
8. ROM必须与构建脚本一起定版, 凭记忆重建=引入新bug
9. 测试必须覆盖两种FLAG态的战斗路径, 不能只测跳过态
10. 观测点选在"注册/调度"层, 不要选"数据写入"层; 发送点≠真实路径(调试代码会伪装成业务代码)
